O mapa mental

As pecas que fazem a colaboracao acontecer.

Entenda a linguagem essencial para navegar por qualquer projeto no GitHub.

R

Repository

A pasta inteligente do projeto. Guarda codigo, historico, documentacao e as regras para todo mundo trabalhar junto.

B

Branch

Uma linha de trabalho independente. Permite experimentar uma funcionalidade sem mexer no codigo principal.

C

Commit

Um ponto salvo no historico. Cada commit registra uma mudanca pequena, com contexto e intencao claros.

PR

Pull Request

A conversa antes da entrega. O time revisa, comenta, melhora e aprova as mudancas antes do merge.

I

Issue

Um lugar para organizar problemas, ideias e tarefas. Da visibilidade ao que precisa ser feito e por que.

A

Actions

Automacao que trabalha por voce: testa o codigo, cria builds e publica entregas a cada evento do projeto.

Do local para o mundo

Um fluxo simples. Uma historia rastreavel.

O ciclo se repete: voce cria, registra, compartilha e recebe colaboracao.

01 / CRIAR

Branch

Abra um espaco seguro para sua mudanca.

02 / REGISTRAR

Commit

Salve uma etapa com uma mensagem que explica o por que.

03 / COMPARTILHAR

Push + PR

Envie ao GitHub e convide o time para revisar.

04 / INTEGRAR

Merge

Una o trabalho aprovado ao projeto principal.

# o caminho mais comum
git checkout -b minha-feature
git add . && git commit -m "Adiciona minha feature"
git push origin minha-feature
Antes de publicar

Pequenas escolhas, grandes diferencas.

Um projeto acolhedor e previsivel facilita a vida de quem chega depois. Estes fundamentos ajudam o time a manter o ritmo.

Escreva commits que contam uma historia

Prefira mensagens no imperativo e descreva uma mudanca por vez. O historico vira uma ferramenta de entendimento, nao um deposito de frases vagas.

Use o README como porta de entrada

Explique o que o projeto faz, como rodar localmente e como contribuir. Uma boa documentacao reduz perguntas repetidas e acelera novas pessoas.

Revise com contexto e respeito

Comentarios em Pull Requests devem melhorar o codigo e tornar a decisao mais clara. Discuta a implementacao, nao a pessoa.

Automatize o que se repete

Com GitHub Actions, tarefas como testes, lint e deploy deixam de depender de memoria e passam a fazer parte do fluxo.
